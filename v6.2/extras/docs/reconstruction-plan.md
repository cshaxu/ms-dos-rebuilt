# MS-DOS 6.20 三核心源码复建执行计划

## 1. 最终目标和边界

以 `O:/repos.hobby/ms-dos-rebuilt/v6.2` 为项目根，主要依据 `O:/repos.hobby/ms-dos-archaeology/v6.0` 复建英文 MS-DOS 6.20 的 IO.SYS、MSDOS.SYS、COMMAND.COM 源码。必要时以 v5.0、DOS 4、OpenNT 辅助判断；参考来源不是目标版本本身。目标是从当前源码全新构建，三个文件分别与镜像中提取的目标逐字节相同，并恢复微软原有文件组织、汇编风格、注释、命名及参数惯例。

范围仅限三个核心组件及其实际需要的共享头文件、消息、构建资源；不扩展到其他 DOS 程序。6.20 本身需要的压缩卷接口等仍属于核心组件范围，不能因 v5.0 曾清理 DoubleSpace 就照搬清理规则。以 DOS 6.0 和 Astro 为主要基线，重点依据目标二进制判断 6.20 版本差异；仅在实际采用 OpenNT 等辅助源码且有具体证据时，检查其特有的宿主依赖。不能机械删除合法 DOS 代码。

保留 `bios/`、`dos/`、`cmd/command/`、`inc/` 及必要的 `messages/` 原式布局。所有项目自增的治理、计划、台账、测试、构建脚本、研究、证据和临时构建文件放 `extras/`；`extras/build/` 不纳入 Git。现有 v5.0 及原始 DOS 6.0 参考只读，不复制其目标哈希、版本常量或目录路径作为 6.20 事实。

参考事实：DOS 6.0 的 `inc/versiona.inc` 为 6.00，不等于 6.20；其树下没有 `messages/`。参考链接表列出 BIOS 15 个模块（另有 MSLOAD）、内核 57 个、COMMAND 35 个；这是参考规模，不预断目标 6.20 的模块、选项或代码完全相同。

## 3. MTSP 阶段、任务和交付

### M0：建立工程及目标基线

**T1 / S1 — 准入与固定输入。** 建立 `v6.2/extras/` 治理结构，移植并按当前用户要求修订 v5.0 的治理/执行规范；登记镜像哈希、几何、三个文件的大小、哈希、FAT 链和提取方法。把三个目标保存在 `extras/` 下明确标记的只读基线位置，并固定哈希，避免依赖临时目录。建立项目专属 `.gitignore`，不把构建输出纳入 Git；参考源码和原镜像永不写入。不得依赖旧 v5.0 项目位置。

交付：目标清单、提取/验证工具、项目规则和当前状态。验收：对提取的三个文件直接比对、大小及 SHA-256 与上表一致；保留镜像截断说明；路径均指向新仓库或明确登记的外部参考。此阶段不声称源代码或目标已复建。

**T1 / S2 — 固定参考和文件顺序。** 从三个参考链接清单和源代码依赖出发，枚举 BIOS、DOS、COMMAND、共享 include、目标消息和可选源码；形成冻结的文件台账：序号、组件、路径、来源、目标相关性、自动分类、状态、证据。顺序固定为 `bios/` → `dos/` → `cmd/command/` → `inc/` → `messages/`，每组按路径不区分大小写排序。链接顺序另记，不与审计顺序混淆。新增必要文件时在台账末尾登记原因，不能改写已有序号。

交付：文件全集、参考哈希及明确的排除清单。验收：每个文件可定位，报告已完成数量、当前序号和剩余数量；本阶段实际数量由枚举确定，不能用 6.0 参考的粗略数量冒充目标文件数。

### M1：DOS 6.0 参考构建与缺口定位

**T2 / S1 — 源码及构建依赖闭包。** 对上述三份链接清单逐项找出源文件、递归 INCLUDE、链接资源和消息生成输入；记录 MASM、LINK、RELOC、消息工具等实际路径、版本和哈希。处理参考树缺少 `messages/` 的问题：优先查找适用于该源码的本地参考消息源；不明或推断的资源必须标注，不能拿 v5.0 消息当作 6.20 已证实内容。历史编译器等只作构建依赖，不纳入三个组件源码。

验收：列出实际可构建集合、缺失项、来源及验证方法，不能将未解决项标记成完成。

**T2 / S2 — 基线构建。** 先按 DOS 6.0 参考源、链接顺序和工具设置构建出参考结果；逐个记录对象、映射、列表、资源和输出哈希，然后与三个 6.20 目标计算差异。若不能构建，定位第一个真实缺口并在同一任务中补齐或留下明确阻塞，不制作候选包。

验收：每个组件都有成功构建记录或确切缺口；记录链接模块、生成步骤、字节差异，不声称 6.0 参考输出等于 6.20。

### M2：定位 6.20 差异并逐文件恢复

**T3 / S1 — 二进制与模块映射。** 为 IO.SYS 的加载器与 BIOS、MSDOS.SYS 和 COMMAND.COM 分别建立长度、段、入口、链接布局和差异区间；结合 MAP/LST、目标反汇编和参考源码，将可证实的差异定位到文件和功能。版本号、资源、结构布局、压缩卷接口均单独标注证据等级：目标直接证实、参考支持的推断或未知。不能从 6.00 改版本常量就宣布复建成功。

**T3 / S2 — 三轮有序处理。** 在冻结顺序上：第一轮标记与适用参考完整相同的文件；第二轮标记代码完全由适用参考相同段落覆盖的文件；第三轮只逐个审计剩余文件。各轮聚焦实际的 6.20 版本差异；仅在引入其他来源的相关代码时按其来源核查。**参考相同只说明来源对应，不自动证明它就是 6.20 的正确实现**：涉及已知目标差异、宏展开、链接布局或关键路径时必须有目标证据。可以保留目标所需的压缩卷相关代码。

逐个文件工作流程：①确认台账当前序号与前置证据；②对照 DOS 6.0、必要的其他参考和目标差异；③确定保留/修改，按微软原风格处理；④必要时构建并比较受影响产物；⑤登记源码前后哈希、参考位置、验证和遗留不确定性，结束该文件后才处理下一个。只能修改当前文件；发现跨文件依赖先记录并调整计划，不能随意跳文件或反复回头。大小写、缩进等纯格式差异，在不改变目标的前提下与 DOS 6 对齐。

第三轮完成后，按相同固定顺序评估第二类能否安全转第一类：完整替换必须不引入错误版本或与 6.20 不符的内容，并通过目标比较；保留的第二类说明原因。不要自动新增无止境的复核轮次。

### M3：三个核心文件逐字节收敛

**T4 / S1 — IO.SYS：** 恢复 MSLOAD 与 BIOS 及其启动/CONFIG/设备依赖，记录目标组件边界和链接布局。验收：干净构建的完整 IO.SYS 长度 40,566，直接逐字节等于固定目标。

**T4 / S2 — MSDOS.SYS：** 恢复内核、文件系统、缓冲区、设备、进程及目标需要的 6.20 接口。验收：完整 MSDOS.SYS 长度 38,138，直接逐字节等于目标；关键布局和目标差异有证据。

**T4 / S3 — COMMAND.COM：** 恢复驻留、瞬态、初始化、解析、命令和消息布局。验收：完整 COMMAND.COM 长度 54,619，直接逐字节等于目标。

组件间如存在前置依赖，可先做只读分析与依赖规划，但生产源码修改仍遵守台账顺序。上述组件任务的编号是验收责任，不授权跨文件跳改。每次修改当前有效构建输入后执行必要构建，整体已可构建时同时比较三个文件，避免破坏已达成的一致性。禁止将现成目标文件或其二进制片段作为构建输入，也禁止生成后修补二进制以伪造一致。依据目标观察手工重建的源码数据可以保留；原始归属未知时必须标注推定和证据，不能冒称已确认的历史源码。

### M4：最终交付

**T5 / S1 — 干净构建与交付。** 在新的隔离构建目录从当前源码重新构建三文件，记录工具哈希、生成资源、链接顺序、输入和输出哈希，并分别作完整字节比较；检查台账无未完成文件，登记参考/目标证据及明确限制。项目以 `v6.2` 工作树交付，构建和治理材料在 `extras/`；不自行制作候选包、ZIP 或部署。目标输出的部署位置尚未指定时不覆盖现有 `O:/DOS` 的 DOS 5 文件。

验收标准：三文件的大小、SHA-256 和逐字节比较均等于第 2 节；源码采用要求的布局和风格；有序文件台账完成；当前构建方法可复用，源代码、推断和未知有区分。不以参考文本匹配冒充目标验证，不声称已知每行都是微软 DOS 6.20 原始源码。

## 4. 日常进度和中断规则

每次报告固定写：阶段/任务；当前第几个文件及总数；已完成、待处理和保留为差异的数量；当前文件具体发现、变更、验证；下一个文件。自动分类可批量执行，人工处理严格按序。三文件目标一致后不再为了治理而反复重建或重复审计；只在源码/构建输入变化或新证据产生实际疑点时验证受影响范围。

永久禁止 Computer Use；需要运行 DOS 构建工具时只用隔离桌面或探针。目标文件逐字节一致是验收标准，无需 SoftPC 或其他虚拟机运行验证；不挂载目标镜像。原始参考与用户已有文件不得覆盖；未经明确要求不发送信息、不发布、不提交、不打包。

## 5. 第一项实际执行工作

**下一步只准入 M0 T1 S1。** 将上面的三个临时提取文件登记到项目的目标基线位置，写入哈希及提取证据；建立 `extras/` 下最小治理和状态文件，并确认 `extras/build/` 被忽略。完成后报告实际文件与目标哈希，再进入 S2 建立冻结文件顺序。当前计划不代表源码已导入或 6.20 已构建。
