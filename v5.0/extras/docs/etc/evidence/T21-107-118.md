107 dos/buf.asm: complete DOS6 diff reviewed, unchanged. Reference manifest
contains DOS6 buf.asm; OpenNT has no same-path buf.asm, and DOS4 has no matching
getb17/BuffInHMA implementation to substitute. Do not claim an exact older
source match for the reconstructed HMA copy sequence.

The necessary instruction difference is confined to getb17. DOS5 restores
disk-read flags before loading/shifting the sector size, then copies the HMA
scratch buffer and jumps past the non-HMA POPF. Therefore the HMA branch's
carry at JC getbx comes from SHR, while the non-HMA branch restores read flags.
DOS6's I001 block instead preserves the disk-read carry across that shift and
copy. Adopting it would change both bytes and behavior. The target is exact
reconstruction, not retroactive bug fixing. The maintained PUSH/POP order is
balanced on both paths; buffer_copy_done joins them without a second copy path.
Its concise comments correctly describe the older flags and do not falsely
attribute the later I001 fix. Existing MASM structure, registers and parameter
style already follow DOS6. Missing trailing EOF markers do not justify a
cosmetic-only rewrite of an otherwise explained file.

The source was compiled in full build cmd-25422-19888, whose MSDOS.SYS exactly
matches the frozen DOS5 target. No change and no new build in this review.
