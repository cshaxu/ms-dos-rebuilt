# Documentation guide

This is the project documentation entry point. Read [current state](states/CURRENT.md), [execution](rules/EXECUTION.md), and [contributing](../CONTRIBUTING.md) before work. For planning also read [roadmap](design/ROADMAP.md), [queue](states/QUEUE.md), and [TODO](states/TODO.md); for source or build work read all four rules and the architecture and source layout. For governance changes read documentation rules and each changed authority.

`design/` owns the goal, architecture, layout and milestones; `rules/` owns constraints; `states/CURRENT.md` owns the active packet and baseline; `QUEUE.md` orders unnumbered proposals; `TODO.md` records deferred debt; `proposals/` holds candidate details; `history/` records closed work; `etc/` indexes supporting evidence. One subject has one authority. Link rather than duplicate.

These rules adapt the neighboring SoftPC project's governance and execution documents to this DOS reconstruction. SoftPC-specific CMake, dual-host architecture, mirror and INI restrictions are not imported as DOS requirements.

Owner-directed sequential source review follows [FILE-REVIEW.md](design/FILE-REVIEW.md); its frozen progress is in [file-review-ledger.json](etc/file-review-ledger.json).
